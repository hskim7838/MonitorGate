# MonitorGate

[English](README.md) | **한국어**

**Ctrl을 누를 때만 다른 모니터로 포인터를 이동하세요.** MonitorGate는 여러 모니터를 사용할 때 포인터가 원하지 않는 화면으로 넘어가는 것을 방지하는 Windows 프로그램입니다.

평소에는 포인터를 현재 모니터 안에 유지합니다. 왼쪽 또는 오른쪽 Ctrl을 누른 채 다른 모니터로 이동하고, Ctrl을 놓으면 도착한 모니터 안에 다시 고정됩니다.

이동 키를 누른 채 마우스를 움직이면 화면 상단 중앙에 **`Pointer movement enabled`** 박스가 표시됩니다. 박스는 포인터가 있는 모니터를 따라가며, 키를 놓거나 약 180ms 동안 움직임이 없으면 숨겨집니다. 기본 색상은 검정 배경과 흰 글씨이며, 설정에서 바꿀 수 있습니다. 클릭이나 작업 중인 창의 포커스를 가로채지 않습니다.

![포인터 이동 상태 박스](overlay-preview.png)

## 실행 환경

- Windows 10 또는 Windows 11
- .NET Framework 4.8
- 확장 모드로 사용하는 여러 모니터

프로그램 실행에는 관리자 권한이나 별도 설치 과정이 필요 없습니다. Python, AutoHotkey, .NET SDK도 필요하지 않습니다. Windows의 디스플레이 설정에서 모니터 배치를 실제 위치에 맞춰 두세요. 가로·세로 및 위아래 배치를 자동으로 읽습니다.

## 설치 및 첫 실행

이 저장소에는 **소스 코드**가 있습니다. 소스를 내려받거나 복제한 폴더에는 실행 파일이 없으므로, 다음 두 방법 중 하나를 사용합니다.

### 배포된 실행 파일 사용

저장소의 **Releases**에 실행용 ZIP이 제공되어 있다면:

1. 실행용 ZIP을 다운로드합니다.
2. 프로그램을 계속 보관할 폴더에 압축을 풉니다.
3. `MonitorGate.exe`를 더블클릭합니다.

### 소스에서 직접 빌드

실행용 배포 파일이 없거나 직접 빌드하려면:

1. 저장소를 복제하거나 **Code → Download ZIP**으로 소스를 내려받고 압축을 풉니다.
2. `Build.ps1`이 있는 폴더에서 PowerShell을 엽니다.
3. 아래 명령을 실행합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
```

4. 같은 폴더에 생성된 `MonitorGate.exe`를 실행합니다.

빌드 스크립트는 Windows의 .NET Framework 컴파일러를 사용하며 외부 패키지를 내려받지 않습니다. 실행 정책 옵션은 해당 PowerShell 실행에만 적용되며 시스템 정책을 변경하지 않습니다.

## 사용 방법

실행 후에는 작업 표시줄의 알림 영역에 **방패 아이콘**이 나타납니다. 보이지 않으면 숨겨진 아이콘 메뉴를 확인하세요.

1. 현재 모니터 안에서 마우스를 평소처럼 사용합니다.
2. 다른 모니터로 이동할 때 **Ctrl을 누른 채** 포인터를 움직입니다.
3. 원하는 모니터에 도착하면 **Ctrl을 놓습니다**.

| 동작 | 방법 |
| --- | --- |
| 다른 모니터로 이동 | Ctrl을 누른 채 마우스 이동 |
| 제한 일시정지 / 재개 | **Ctrl+Alt+F9** |
| 종료 및 제한 해제 | **Ctrl+Alt+F10** |
| 설정 열기 | 방패 아이콘 우클릭 → **설정...** |
| 이동 키 변경 | 방패 아이콘 우클릭 → **모니터 이동 키** |
| 상태 박스 표시 ON/OFF | 방패 아이콘 우클릭 → **이동 상태 박스 표시** |
| 트레이에서 일시정지 / 재개 | 방패 아이콘 더블클릭 또는 우클릭 메뉴 |

단축키를 다른 프로그램이 사용 중이면 시작 알림에 표시됩니다. 이때는 트레이 메뉴를 사용하세요. 한 번에 하나의 MonitorGate 인스턴스만 실행할 수 있습니다.

## 설정

방패 아이콘을 우클릭하고 **설정...**을 선택합니다. 변경한 뒤 **저장**을 누르세요.

| 설정 | 동작 | 처음 실행할 때의 기본값 |
| --- | --- | --- |
| 모니터 이동 키 | 누르는 동안 모니터 간 이동을 허용할 키. Ctrl, Alt, Shift, 오른쪽 Ctrl 중 선택 | Ctrl |
| Windows 로그인 시 자동 실행 | 현재 사용자가 Windows에 로그인한 뒤 실행하도록 등록 | OFF |
| 실행할 때 포인터 제한 켜기 | ON이면 프로그램 시작 시 제한 적용, OFF이면 일시정지 상태로 시작 | ON |
| 이동 상태 박스 표시 | 이동 키를 누른 채 움직일 때 상단 박스 표시 | ON |
| 박스 배경색 / 박스 글자색 | 색상 선택 버튼으로 각각 변경하고 미리보기 확인 | 검정 / 흰색 |
| 글꼴 / 글자 크기 / 굵게 | 컴퓨터에 설치된 글꼴, 6~48pt 크기, 굵기 선택 | Segoe UI / 9.75pt / 보통 |
| 박스 자동 크기 | 글꼴·크기·굵기에 맞춰 박스 크기 계산 | ON |
| 박스 너비 / 높이 | 자동 크기를 끄고 직접 지정. 100% 배율을 기준으로 입력 | 224 / 28px |

박스 표시를 끄더라도 포인터 제한과 키를 통한 모니터 이동은 계속 작동합니다. Ctrl 이외의 이동 키를 선택하면 해당 키를 누른 채 움직일 때 박스가 나타납니다.

색상을 선택하면 설정 창의 미리보기에 바로 반영됩니다. **저장**을 눌러 실제 박스에도 적용하세요. **취소**는 변경 내용을 버리고, **기본 색상 복원**은 배경과 글자색만 검정·흰색으로 되돌립니다.

글꼴·크기·굵기를 바꾸면 박스 크기도 미리보기에서 확인할 수 있습니다. 미리보기는 현재 화면에서의 실제 크기로 표시하며, 큰 박스는 안쪽을 스크롤해서 확인합니다. 직접 입력한 박스가 너무 작으면 글자가 잘리지 않도록 최소 크기를 적용하고, 화면보다 크면 화면 안에 맞춥니다. 표시되는 실제 크기는 모니터의 배율에 따라 달라집니다.

선택한 글꼴이 굵게 표시를 지원할 때만 굵기를 바꿀 수 있습니다. 저장했던 글꼴이 삭제되면 사용할 수 있는 시스템 글꼴로 표시합니다. **기본 모양 복원**은 글꼴·크기·굵기·박스 크기 설정을 기본값으로 돌리며, 선택한 색상은 유지합니다.

이동 키, 시작 시 제한 상태, 박스 표시 여부, 색상, 글꼴과 크기는 다음 실행에도 유지되며 `%LOCALAPPDATA%\MonitorGate\settings.ini`에 저장됩니다. 실행 중 일시정지는 **실행할 때 포인터 제한 켜기** 설정과 별개입니다.

### Windows 로그인 시 자동 실행

프로그램을 계속 보관할 폴더에서 자동 실행을 켜세요. 폴더를 옮겼다면 자동 실행을 껐다 켜서 새 위치로 등록합니다. 자동 실행은 로그인 이후 시작되며, Windows가 실행을 잠시 지연할 수 있습니다.

Windows의 **설정 → 앱 → 시작 프로그램** 또는 작업 관리자에서 MonitorGate를 비활성화했다면 해당 설정도 다시 켜야 합니다. 설정 창의 **Windows 시작 앱 설정 열기** 버튼으로 이동할 수 있습니다.

## 문제 해결

- **포인터를 자유롭게 움직이고 싶을 때:** Ctrl을 누른 채 이동하거나 Ctrl+Alt+F9로 제한을 일시정지합니다.
- **복사나 선택 중 다른 모니터로 넘어갈 때:** Ctrl+C, Ctrl+클릭 등 원래 키 동작은 유지되므로 Ctrl을 사용하는 동안에는 이동도 허용됩니다. 이동 키를 **오른쪽 Ctrl**로 바꾸면 평소 단축키와 겹치는 일을 줄일 수 있습니다.
- **게임이나 원격 제어 도구와 충돌할 때:** 해당 프로그램도 포인터를 제한할 수 있습니다. MonitorGate를 일시정지한 뒤 사용하세요. 전체 화면 환경에서는 상태 박스가 가려질 수 있습니다.
- **강제 종료 후 포인터 제한이 남아 있을 때:** 프로그램 폴더의 `Release.cmd`를 실행합니다. 실행 중인 MonitorGate를 종료하고 포인터 제한을 명시적으로 해제합니다. 다른 프로그램이 설정한 제한도 해제할 수 있습니다.
- **특정 창에서 키 감지가 늦거나 제한될 때:** 관리자 권한으로 실행된 창, 보안 화면, Windows 스케줄링 등이 감지에 영향을 줄 수 있습니다. 프로그램은 잠금 화면, UAC 보안 화면, 절전 중 제한을 중단하고 일반 화면으로 돌아오면 다시 적용합니다.

포인터 제한은 MonitorGate가 실행 중일 때만 적용됩니다. 정상 종료 시 프로그램이 설정한 제한을 해제합니다.

## 삭제

1. 설정에서 **Windows 로그인 시 자동 실행**을 끕니다.
2. MonitorGate를 종료합니다.
3. 프로그램 폴더를 삭제합니다.

저장한 설정까지 지우려면 `%LOCALAPPDATA%\MonitorGate` 폴더도 삭제합니다.

## 개발자 안내

핵심 코드는 `MonitorGate.cs`, 설정 및 자동 실행은 `StartupSettings.cs`, 설정 창은 `SettingsDialog.cs`, 박스 글꼴·측정·그리기는 `OverlayAppearance.cs`에 있습니다. 실행 중인 파일을 다시 빌드하려면 프로그램을 먼저 종료하세요.

`MonitorGate.csproj`를 Visual Studio/MSBuild로 빌드하려면 해당 개발 도구와 .NET Framework 4.8 참조 어셈블리가 필요합니다. `Build.ps1`을 사용하는 방법에는 .NET SDK나 외부 패키지가 필요 없습니다.

회귀 테스트 실행:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Verify.ps1
```

테스트는 가상 모니터와 테스트용 저장소를 사용하므로 실제 포인터, 키 입력, Windows 자동 실행 등록을 변경하지 않습니다.

| 명령 | 용도 |
| --- | --- |
| `MonitorGate.exe RightCtrl` | 이번 실행에만 오른쪽 Ctrl 사용. `Ctrl`, `Alt`, `Shift`도 가능 |
| `MonitorGate.exe --paused` | 제한을 일시정지한 상태로 시작 |
| `MonitorGate.exe --settings` | 새 인스턴스를 시작하면서 설정 창 열기 |
| `MonitorGate.exe --diagnose monitors.txt` | 포인터 제한이나 키 훅 없이 모니터 진단 파일 생성 |
| `MonitorGate.exe --release` | 실행 중인 프로그램 종료 및 포인터 제한 해제 |
| `MonitorGate.exe --startup` | 자동 실행 등록에 사용하는 인수. 저장한 설정으로 시작 |

검증 범위는 [VALIDATION.md](VALIDATION.md), 변경 기록은 [CHANGELOG.md](CHANGELOG.md)를 참고하세요.
